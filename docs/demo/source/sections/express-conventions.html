Patterns & gotchas

Shopfront's server is a small, conventional Express 4 app. The gotchas are mostly what it leaves out: error handling, 404s, and a real staff check. Sources: server/index.js, server/auth.js, server/routes/.

Conventions here

  • One router per resource in server/routes/, mounted under /api/<resource> in server/index.js.
  • Export the app, listen only when run directly (require.main === module), so tests can import it.
  • Parameterized SQL: $1 placeholders with a values array, never string concatenation.
  • Errors as JSON: res.status(4xx).json({ error: '…' }).
  • Gate a group of routes by passing middleware to app.use before the router (server/index.js:10).

Gotchas

  • A failed query crashes the server. Every handler is async with no try/catch. In Express 4 a rejected promise isn't passed to next; it's an unhandled rejection, which crashes the process on current Node versions (the Dockerfile uses node:20-slim). See error handling.
  • Stack traces reach clients. No (err, req, res, next) handler is registered and NODE_ENV isn't set anywhere in the repo, so Express's default handler sends the stack trace, e.g. for a request with invalid JSON (a 400 from express.json()).
  • Missing rows return 200. GET /:id sends rows[0] even when it's undefined, instead of a 404.
  • The staff check trusts a header. requireStaff accepts any request with an x-staff-role header, whatever its value. Its comment says staff come from a signed SSO cookie (server/auth.js:1-3). Safe only if a proxy always strips or sets that header; reported as a repo problem.
  • The admin endpoint is a stub: it echoes the body without saving (server/routes/products.js:6).
