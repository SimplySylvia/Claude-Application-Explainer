Guided walkthrough

Follow one request, POST /api/orders, from the caller to the database and back. It touches every Express idea Shopfront uses. Sources: server/index.js, server/routes/orders.js, server/db.js.

1 · A client sends the request

Nothing in Shopfront's client calls the API yet, so the caller today is a test or a tool like curl. A browser client would send the same request with fetch:

POST /api/orders HTTP/1.1
Content-Type: application/json

{"items": [{"productId": 42, "qty": 1}]}

2 · Middleware parses the body

Express runs middleware in the order it was registered. The first one, express.json(), reads the JSON body and puts it on req.body. Without it, req.body would be undefined. Concept: middleware.

const app = express();
app.use(express.json());
app.use('/api/products', products);
app.use('/api/orders', orders);
app.use('/api/admin', requireStaff, products.admin);

3 · The router matches the path

/api/orders matches the orders router's prefix, so Express hands it the rest of the path (/). Inside the router, router.post('/', …) matches the method and path. Concept: routers.

router.post('/', createOrder);
router.get('/:id', async (req, res) => res.json((await db.query('select * from orders where id=$1', [req.params.id])).rows[0]));

4 · The handler validates and responds

createOrder rejects an empty or missing cart with 400, before touching the database. Otherwise it inserts the order and responds 201 with the new id. Concept: request and response.

async function createOrder(req, res) {
  if (!Array.isArray(req.body.items) || !req.body.items.length) return res.status(400).json({ error: 'empty cart' });
  const { rows } = await db.query('insert into orders(items) values ($1) returning id', [JSON.stringify(req.body.items)]);
  res.status(201).json({ id: rows[0].id });
}

5 · The database

db.query runs on a shared pg pool. Values go in as $1 parameters, never pasted into the SQL string. Where the flow stops today: the repo has no schema or migrations for the orders table, and the handler has no try/catch, so a database error crashes the server process instead of returning a 500 (see Patterns & gotchas). The PostgreSQL walkthrough picks up from here.

const { Pool } = require('pg');
module.exports = new Pool({ connectionString: process.env.DATABASE_URL });

Try it yourself

Steps 1–4 run without a database, because the empty-cart check returns before any query. The existing test does exactly that:

npm test   # runs test/orders.test.js: POST /api/orders with an empty cart → 400

npm run dev   # API on :4000
curl -i -X POST http://localhost:4000/api/orders \
  -H 'Content-Type: application/json' -d '{"items": []}'   # → 400 {"error":"empty cart"}

A non-empty cart reaches step 5, which needs a local Postgres in DATABASE_URL with an orders table. The repo doesn't define that table, so that part can't be run from the repo as it stands.
