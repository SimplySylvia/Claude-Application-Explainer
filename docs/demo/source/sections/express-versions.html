Versions & what changed

Shopfront allows any Express 4.x from 4.19.2, and with no lockfile a fresh install gets the newest 4.x, so nobody can tell from the repo which version a given environment runs. Express 5 is the current major. Checked 2026-10-13. Sources: package.json:10 (no lockfile committed).

LineIn ShopfrontLatestWhat changed that matters here
express 4^4.19.2; a fresh install resolves to 4.22.34.22.3, 2026-09-14 (release)Security fixes after 4.19.2: 4.20.0 CVE-2024-43796, XSS via res.redirect() (advisory); 4.21.1 a cookie fix; 4.22.3 CVE-2026-4867 in path matching. Shopfront doesn't redirect, but it should still be on ≥ 4.22.3. 4.20.0 also changed some defaults (urlencoded depth, redirect body), none used here (4.x history).
express 5—5.3.0, 2026-10-09 (release)Node 18+. Rejected promises go to next automatically, which would fix Shopfront's crash-on-query-error. Stricter path syntax (named wildcards, no regex characters in strings), req.query read-only, several old methods removed (Migrating to 5).

Upgrade path

1. Commit a lockfile so the version is reproducible. 2. Move to the latest 4.x. 3. Read the migration guide: Shopfront's routes use plain :id paths, so the path-syntax changes shouldn't bite. 4. Try the official codemod, then run the tests:

npx codemod@latest @expressjs/v5-migration-recipe
npm install express@5 && npm test

Everywhere else, this guide describes Express 4, the version Shopfront runs.
